# Near-me search + map view — design

Date: 2026-08-21 · Branch: `feature/near-me-map-search`

## Goal

Let a prospective student find flight schools by *where they are*: search within a radius of their current location (or a chosen airport/city), sort by distance, and see results on a map. This is item 1 of the feature backlog and the prerequisite for the queued per-school Google Map.

## Decisions already made

- Map provider: **Google Maps JavaScript API** (matches the queued per-school map; one map stack).
- Origin input: **browser geolocation + airport/city pick**. No ZIP/address geocoding in this pass.
- Scope: **`/search` only**. State/city/airport pages and the school detail map are follow-ups that reuse the same component.
- Distance is computed **client-side** (Haversine) over the payload `/search` already ships. A Postgres `earthdistance` RPC is deferred until the catalog is too large to ship to the browser.
- Schools that share an airport collapse into **one map pin with a count** (no clusterer dependency).
- Map view **replaces** the result grid (List | Map toggle), on all breakpoints.

## Data model

Migration `supabase/add-coordinates.sql` (idempotent; also folded into `schema.sql`):

```sql
alter table public.airports
  add column if not exists latitude  double precision,
  add column if not exists longitude double precision;
alter table public.airports
  add constraint airports_latitude_range  check (latitude  is null or latitude  between -90  and 90),
  add constraint airports_longitude_range check (longitude is null or longitude between -180 and 180);
-- same two columns + constraints on public.flight_schools
-- plus a guarded backfill of the 18 seeded airports by ICAO
```

- `airports.latitude/longitude` — the airport reference point (ARP). Nullable so unknown airports can still be inserted by the submission approval flow; filled for every seeded airport.
- `flight_schools.latitude/longitude` — optional per-school override (hangar/office location). Owners may edit it (it is *not* added to the protected-columns trigger). This is the column the queued "Google Map location per school" feature writes.
- **Effective position** of a school = its own override, else its primary airport's position, else none (excluded from distance filtering and from the map, counted in an "N schools without a map location" note).
- Both pairs are stored as two `double precision` columns, not PostGIS, because all distance math happens in the browser and the only server-side use is read/write of the raw values.
- `src/lib/supabase/database.types.ts` gains the four columns; `src/lib/mock-data.ts` airports gain `coords`; `supabase/seed.sql` is regenerated by `scripts/generate-seed.ts`; `supabase/README.md` lists the new patch file and the map env vars.

## Types & helpers

`src/lib/types.ts`
- `export type LatLng = { lat: number; lng: number }`
- `Airport.coords?: LatLng`, `FlightSchool.coords?: LatLng` (override only).

`src/lib/geo.ts` (pure, unit-tested with `node:test` in `scripts/tests/geo.test.ts`)
- `haversineMiles(a: LatLng, b: LatLng): number`
- `RADIUS_OPTIONS = [25, 50, 100, 250] as const`, `DEFAULT_RADIUS = 50`, `parseRadius(param): Radius`
- `formatNearParam(origin: NearOrigin): string` / `parseNearParam(param, lookup): NearOrigin | null` where
  `NearOrigin = { kind: "geo", coords } | { kind: "airport", icao, coords, label } | { kind: "city", slug, coords, label }`;
  serialised as `near=33.4608,-111.7283` | `near=kffz` | `near=city:mesa`. Lat/lng are rounded to 4 dp and range-checked; bad input → `null` (ignored).
- `centroid(points: LatLng[]): LatLng | undefined` — used for city origins (mean of the city's airports).
- `formatMiles(n)` → `"42 mi"` / `"<1 mi"`.

`src/lib/data.ts` — `toAirport` / `toSchool` map the new columns to `coords` when both values are non-null.

## `/search` page (server)

Adds to the existing `Promise.all`: `getAirports()`. Computes:
- `schoolData[i].coords` = `school.coords ?? airportByIcao[school.primaryAirportCode]?.coords`
- `airportOptions: { icao, name, location, coords }[]` (only airports with coords)
- `cityOptions[i].coords` = centroid of that city's airports with coords (may be undefined)

No other server changes. Metadata description mentions "near you".

## `AdvancedSearchExplorer` (client)

New state, all URL-synced alongside the existing params:
- `origin: NearOrigin | null` (`near`), `radius` (`radius`, default 50, omitted from URL at default), `view: "list" | "map"` (`view`, omitted at `list`), `sortBy` gains `"distance"`.
- `geoStatus: "idle" | "locating" | "denied" | "unavailable"` — not in URL.

Filter panel gets a **Location** block at the top:
1. Button "Use my location" (icon `LocateFixed`). Calls `navigator.geolocation.getCurrentPosition` with `{ timeout: 10000, maximumAge: 300000 }`; success → `origin = { kind: "geo", coords }`. Denied/unavailable → inline `Notice tone="error"` "Location access was denied — pick an airport or city instead." Insecure context or no API → `unavailable` notice.
2. Single-select typeahead "or near an airport / city" over `airportOptions` + cities-with-coords; matches name, ICAO/IATA/FAA LID, city name. Selecting sets `origin` (kind airport/city). Reuses the existing `TypeaheadFilter` with a one-item `selectedItems` list so the chosen origin shows as a removable chip.
3. Radius chips 25 / 50 / 100 / 250 mi (`Chip`), only shown when an origin is set.

Filtering: when `origin` is set, a school passes only if it has `coords` and `haversineMiles(origin.coords, coords) <= radius`. Distance is memoised per school in the same pass (`distanceMiles` on the filtered item) so sort and cards don't recompute it.

Sorting: `"distance"` chip appears only when `origin` is set; setting an origin switches `sortBy` to `distance`/`asc` unless the user has since picked another sort; clearing the origin falls back to `rating`/`desc` if sort was `distance`.

Cards: when `origin` is set, show `formatMiles(distanceMiles)` in mono next to the airport code.

Results header: a two-chip **List | Map** toggle next to the sort chips. `activeFilterCount` counts the origin as one filter; `resetFilters` clears origin, radius, geoStatus and view.

Map view: renders `<SchoolsMap>` in place of the grid with **all** filtered schools (paging does not apply). The "N schools found" count stays. A small note "{k} schools have no map location" appears when `k > 0`.

## `SchoolsMap` (new client component, `src/components/SchoolsMap.tsx`)

Props: `schools: { id, name, href, airportCode, location, rating, reviewCount, coords, distanceMiles? }[]`, `origin?: { coords, label }`, `radiusMiles?: number`, `className?`.

- Loads Google Maps with `@googlemaps/js-api-loader` v2: `setOptions({ key, v: "weekly" })` once (module scope guard), then `importLibrary("maps")` + `importLibrary("marker")` in an effect. Missing `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` → render `Notice tone="info"` explaining the map needs the key; never throw. Load failure → `Notice tone="error"`.
- Map options: `mapId: NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID ?? "DEMO_MAP_ID"`, `colorScheme` from `useTheme().resolvedTheme` (map is re-created when the theme changes), `mapTypeControl: false`, `streetViewControl: false`, `gestureHandling: "cooperative"` on every breakpoint — the map is wide on desktop and also lives in the sticky sidebar card on school pages, where `"greedy"` would capture page scroll whenever the pointer crosses it.
- Pins: group schools by effective-coords key (`lat,lng` at 4 dp). One `AdvancedMarkerElement` per group; its `content` is a DOM pill: accent background, white ICAO text in the mono face, and a count badge when the group has >1 school. Click → single shared `InfoWindow` listing the group's schools (name link → `href`, location, stars-as-text "4.6 · 12 reviews").
- Origin: a distinct `AdvancedMarkerElement` (sky-blue dot) + `google.maps.Circle` for the radius (accent stroke, 8% fill).
- Viewport: `fitBounds` to all pins (+ circle bounds when present) with padding; single pin → zoom 11. Re-fit when the school set changes, not on every re-render.
- Empty set → centred muted message inside the map container; container keeps a fixed height (`h-[70vh] min-h-[420px]`, rounded, `border-line`).
- Cleanup: markers' `map = null`, circle `setMap(null)`, InfoWindow closed on unmount/re-create.
- Accessibility: container has `role="region" aria-label="Map of matching flight schools"`; the list view remains the accessible path (toggle is a pair of `Chip`s with `aria-pressed`).

## Config

- `.env.local`: `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY=` (required for the map; restrict the key to HTTP referrers and to the Maps JavaScript API) and optional `NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID=`.
- New dependency: `@googlemaps/js-api-loader` (pinned), `@types/google.maps` (dev, pinned).
- No CSP is configured in this project; nothing to change.

## Error handling summary

| Situation | Behaviour |
|---|---|
| Geolocation denied / unavailable / timeout | Inline notice; origin unchanged; picker still works |
| `near` param malformed or unknown ICAO/city | Ignored (treated as no origin) |
| School without coords while origin set | Excluded from results; counted in the note |
| Map API key missing | Info notice in place of the map; list view unaffected |
| Map script fails to load | Error notice; toggle back to list works |

## Out of scope
